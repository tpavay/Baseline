Design decisions

Two altitudes, one sheet PROPOSED

The hub separates Build a plan (a program spanning weeks) from Add a workout (one session). Groups make the altitude obvious instead of mixing a multi-week program next to “blank workout.”

Execute now vs. author reusable YOUR CALL

Start an empty session drops you into a live, recording workout (log as you train — no date, no plan). Authoring a reusable workout lives under From a template → Create new template. Two different jobs, no longer conflated.

Log by talking, not tapping EXPLORING

Inside an empty session you can just say it — “three 13-min tempo runs at 6:45, 6:40, 6:42” → Baseline structures it into a logged exercise with sets. The mic is always in reach; typing works too. Direct-tap logging stays for corrections.

AI is the fast path, not the only path PROPOSED

“Build with Baseline” sits on top as the hero, but empty session / template / import are peers below it — matching the product principle that conversation and direct controls are complementary.

Import stays honest PROPOSED

Import never dead-ends on a guess: unreadable values are flagged amber for confirmation, and the draft lands day-owned on the Plan calendar.

Plan tab · one “add,” not two DECIDE

You're right that a top-right ＋ plus a per-day ＋ Add workout reads as two competing adds. Proposed fix in the mock: the top-right becomes a calendar / jump control (a real, different job), and adding is only ever the scoped per-day row — the sheet then says “Add to Wednesday,” so you always know which day. I also added a compact week summary (planned / done / duration) for context. Which add-model do you want?
